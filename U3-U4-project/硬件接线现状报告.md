## 0. 项目背景（一句话）

生态环境情感化转译设备：Arduino Uno 采集多路环境传感器数据，通过 USB 串口把 JSON 数据发给树莓派 4B，树莓派跑液态神经网络（CfC + AutoNCP）把环境压力转译成情感化的光/声/振动表达。详见项目内 `SERIAL_PROTOCOL.md` 和 `基因组预设与传感器推理设计.md`。

### 1.0 ⭐烧录必读：Clock Source 必须设成 16MHz（否则烧录必失败）

**这是这块板子最大的坑，务必先看。** 在 Windows 电脑用 Arduino IDE 烧录时：

- **工具(Tools) → Clock Source（时钟源）→ 必须选 16MHz**（Internal 16MHz 或 External 16MHz），**不能用默认的 "Internal 32MHz"**。
- 症状：如果选了 32MHz，烧录会在"写入flash"阶段报 `not in sync` / `out of sync`、收到一堆垃圾字节（0x5b/0xbe/0x7a等），编译能过但就是写不进去。
- 原因：这块板子实际是**外部16M晶振**（商品详情明确写"主频：外部16M晶振，最大配置内部32M"），时钟源设成32MHz会导致烧录通信时序错乱。
- 这个问题会伪装成"USB线坏了/端口问题/供电不足/波特率问题"，换线换口降速全都没用，**唯一正解是改 Clock Source 为 16MHz**。（2026-07-05 实测确认）
- 其他相关设置（工具菜单）：Upload speed 用 57600、Variant 用 328P-LQFP32、板子选 LGT8F328（只有一个条目，自动识别的就是对的）。

### 1.1 Arduino代码烧录方式（重要，别踩坑）

- 这块Uno板子（CH340驱动的兼容板）的bootloader实际工作波特率是 **57600**，不是标准Uno默认的115200。
- 已确认：树莓派上通过avrdude/arduino-cli给这块板子烧录程序时，握手能成功，但**批量数据写入/读取阶段必定失败**（稳定复现，一度怀疑是树莓派这颗CH340芯片的Linux内核驱动在处理较大USB数据块时的兼容性问题，非接线问题，非供电问题——已逐一排除）。
- **补充确认（更关键的一层原因）**：在Windows电脑上用Arduino IDE烧录时，串口监视器里显示这块板子被识别为 **LGT8F328**，不是原装ATmega328P——**这块板子实际芯片型号是 LGT8F328P**（某厂商推出的引脚/大部分功能兼容ATmega328P的替代芯片，但底层不是Atmel/Microchip原厂硅片）。这与树莓派上avrdude报的芯片签名"ATmega328P/LGT8F328P"两者歧义完全吻合，说明之前树莓派烧录失败很可能不只是CH340驱动的锅，**这颗LGT8F328P芯片的bootloader/编程协议细节本身跟标准AVR就有差异**，两个因素大概率叠加导致了那次持续失败。
- **结论不变，且证据更充分**：Arduino程序烧录统一走"接回Windows电脑，用Arduino IDE烧"这条路，树莓派只负责通过串口**读**Arduino发来的数据。另外，Arduino IDE里选板子时如果有专门的"LGT8F328"相关板卡包（而不是通用"Arduino Uno"），建议使用专门的板卡定义，兼容性更好。

## 2. 传感器接线现状

固定串口协议见 `SERIAL_PROTOCOL.md`，波特率 `115200`（这是Arduino与Pi之间业务数据通信的波特率，跟上面提到的"烧录时57600"是两码事，不要混淆）。

| 传感器 | 型号 | 引脚分配 | 供电电压 | 状态 | 对应SERIAL_PROTOCOL字段 |
|---|---|---|---|---|---|
| 光敏电阻 | 光敏电阻模块（分压式） | 模拟输出 → **A0** | 5V | ✅已接 | `light`（需后续换算/替换为BH1750校准逻辑，见第3节） |
| 土壤湿度 | 电容式土壤湿度传感器（Grove接口：SIG/NC/GND/3V3） | SIG → **A1**，3V3 → Arduino 3.3V，GND → GND，NC悬空不接 | **3.3V**（注意不是5V） | ✅已接，**已标定**（2026-07-05：空气中0-4，泡水350-370，见固件`SOIL_DRY_RAW`/`SOIL_WET_RAW`。注：第一颗传感器实测坏了，排查后换新的解决，跟接线/代码无关） | `moisture` |
| 声音 | MAX4466（驻极体麦克风放大板，模拟输出，非INMP441数字麦克风） | OUT → **A2** | 5V | ✅已接 | `sound`（代码里需连续采样取峰峰值，不能单次analogRead，见第4节） |
| 气压/温湿度 | BMP280 | I2C：SDA → **A4**，SCL → **A5** | 板载稳压（3.3V逻辑，模块通常兼容5V输入） | ✅已接 | 项目正式传感器方案里用BME680替代BMP280（多测VOC），当前BMP280是否保留/如何映射到`voc`/`humidity_air`字段待决策 |
| 温湿度 | DHT系列 | 数字信号 → **D2** | 5V | ✅已接 | 与BME680功能重叠，去留待决策（同上） |
| 人体感应 | PIR模块 | — | — | ❌已决定移除，不用于正式方案 | 不对应任何字段 |
| pH | PH-4502C | 计划：Po（模拟输出）→ **A6**，Do悬空不接，+ → 5V，- → GND，另有BNC接口接玻璃pH探头 | 5V | ⏸**暂停，尚未接线** | `ph` |
| EC/电导率 | TDS模块 | AOUT → **A7**，VCC → 5V，GND → GND，另有2孔接口接防水TDS探头 | 5V | ✅已接（2026-07-05），固件已启用`ENABLE_EC`，**暂用厂商默认经验公式，未做精确标定**（待办：用342/707ppm标准校准液标定） | `ec` |

## 3. 与"官方传感器方案"的差异（待决策事项）

项目文档 `基因组预设与传感器推理设计.md` 中定义的官方7通道硬件方案是：DS18B20（温度探针）、电容式湿度、**BME680**（温度/湿度/气压/VOC一体）、**BH1750**（光照，数字量）、INMP441（声音，数字I2S）、PH-4502C、TDS模块。

当前实际硬件与官方方案的差异：

1. **温度/气压/VOC**：官方方案用BME680一体模块（含VOC传感），当前实际接的是分离的 DHT（温湿度）+ BMP280（气压），**没有VOC测量能力**。是否购置BME680替换、或者接受当前方案降级（`voc`字段长期缺失，软件端按"缺失字段"处理即可，不会报错），待用户决策。
2. **光照**：官方方案用BH1750（数字I2C接口，直接输出lux值，无需自己标定ADC）。当前用的是模拟光敏电阻分压电路，读到的是原始ADC值，**需要在Arduino代码里自行做经验换算成lux近似值**（不如BH1750精确，但够用）。是否升级为BH1750待决策。
3. **声音**：官方方案用INMP441（数字I2S麦克风），Arduino Uno无硬件I2S支持，已改用MAX4466模拟麦克风方案替代，功能等效（都是给出"相对声音强度"），**此项已定案，不算待决策项**。
4. **人体感应PIR**：不在官方7通道方案内，已决定移除。

## 4. Arduino代码待办事项（接线完成后要处理）

- [ ] 声音传感器：单次`analogRead()`没有意义，需要在几十毫秒窗口内连续采样，取峰峰值(max-min)作为`sound`强度指标。
- [ ] 土壤湿度、pH、EC 三个模拟传感器都需要各自**标定**（ADC原始值 → 物理单位），不能把0-1023原始值直接发给树莓派（`SERIAL_PROTOCOL.md`第4节明确要求）。
- [ ] 缺失/未接的传感器字段，直接不写入JSON的key，不要发`null`或`0`（尤其pH，发0会被当成极端酸性误判）。
- [ ] 波特率用 `115200`（业务数据通信），与烧录时avrdude用的57600无关，不要写错。
- [ ] 每2秒左右发送一行JSON，格式严格参照`SERIAL_PROTOCOL.md`示例。
